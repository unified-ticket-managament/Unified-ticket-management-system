# Production Checklist

## Before pushing to `main` (which triggers an automatic EC2 deploy — see [09-deployment](../09-deployment/README.md))

- [ ] Both Alembic chains apply cleanly against a copy of production's schema (or a Neon branch of it) — not just your local dev database.
- [ ] Any autogenerated migration has been manually reviewed for unrelated dropped indexes/columns (a real, recurring drift pattern in this codebase).
- [ ] Any new Postgres enum member uses `ALTER TYPE ... ADD VALUE IF NOT EXISTS`, per the repo's own `add-postgres-enum-value` skill.
- [ ] `npx tsc --noEmit` is clean in `unified-frontend` (the de facto lint gate, since `npm run lint` is broken).
- [ ] Backend tests that touch the database were run **individually**, not all together (three known files hang if run in the same pytest process — see [11-testing](../11-testing/README.md)).
- [ ] If the change touches SLA/escalation timing, verified against a database at the correct migration head, not assumed correct from local behavior alone.

## Immediately after a deploy

- [ ] `GET /health` on the deployed environment.
- [ ] `GET /docs` reachable (confirms the app built its OpenAPI schema without error).
- [ ] One real authenticated request succeeds (confirms DB connectivity, not just process liveness).
- [ ] Confirm the SLA scheduler restarted (`Scheduled SLA sweep completed` log lines resume on the expected cadence).
- [ ] If the deploy touched CORS-relevant config, confirm a real browser login still works — not just a `curl` request (browser CORS preflight behavior differs from a bare curl).

## Periodically (not deploy-triggered)

- [ ] Confirm which environment(s) are genuinely live production — this documentation set could not determine this conclusively from the repository alone; re-verify this hasn't silently changed.
- [ ] Confirm the Microsoft Graph webhook subscription hasn't lapsed (it requires periodic renewal).
- [ ] Confirm `JWT_SECRET_KEY` rotation, if ever needed, is scheduled deliberately and communicated — not treated as a routine env var change (it forces a global logout).

## Before rotating any secret

- [ ] Understand `Settings`'s `@lru_cache` behavior — the running process must be **restarted**, not just have `.env` edited, for the new value to take effect.
- [ ] For `JWT_SECRET_KEY` specifically: communicate the forced global logout to users/stakeholders beforehand.
