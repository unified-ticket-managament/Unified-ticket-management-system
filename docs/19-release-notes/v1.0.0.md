# v1.0.0 — Current Production State

Synthesized from root `CLAUDE.md`'s dated engineering log. "v1.0.0" is this documentation set's own label for "everything confirmed live as of this pass" — not a tag that exists in git.

## Major features (chronological, as best determined from the log)

- **Service unification**: three originally-separate repositories (RBAC backend+frontend, Ticketing backend+frontend) merged into one monorepo; backends consolidated into `unified-backend`; frontends consolidated into `unified-frontend` (embedding the ticket workspace).
- **SLA & Escalation**: two independent clocks (First Response, Resolution), a four-tier breach ladder, an escalation ownership-handoff chain, Escalation Handling SLA, CRITICAL priority tier.
- **OTP Rule → Response SLA auto-stop** (2026-08-14/15): an OTP rule match stops the First Response clock immediately; real per-email SLA state exposed to Mail.
- **RBAC permission compliance audit** (2026-07-14/15): a full audit against a ground-truth permission matrix; fixed a critical unauthenticated-attachment-upload bug, an unconditional Team-Lead close/reopen bypass, and added the RBAC domain's first real permission checks on several routes.
- **Organization Structure** (2026-07-17): Reporting Manager assignment (Account Manager ↔ Category), a dynamic per-viewer organization chart, widened company-wide ticket-assignment for Account Managers.
- **Profile module** (2026-07-17): ten real `users` columns replacing a client-only mock store; a real Employee ID; Settings relocated into Profile.
- **Notifications: SSE** (2026-07-22): replaced 30-second bell polling with real-time Server-Sent Events; found and closed a real DB-connection-pool scaling risk in the SSE auth dependency's design.
- **Notifications: business-critical email** (2026-08-06): a fixed, centralized policy sends real email for a specific notification-type allowlist, on top of the unchanged in-app path.
- **Employee data cleanup** (2026-08-10): removed 25 dummy/demo `users` rows against an official 99-employee master list; seed script pared down to prevent recurrence.
- **Employee Number** (2026-08-10): a real, human-readable `employee_number` column, backfilled from official source data; a later gap (missing from Create User) found and fixed 2026-08-18.
- **Ticket numbering** (2026-08-10): a contiguous-renumbering fix correcting a stale-backfill artifact (`TKT-06` jumping to `TKT-187`).
- **Internal Note recipients** (2026-08-11): real "To" delivery, replacing a purely cosmetic UI field; a new, deliberately hierarchy-free recipient-listing endpoint.
- **Forwarded mail visibility fix** (2026-08-15): closed a 403 gap for `communication:view_all` holders opening a forwarded pending item.
- **Inbound Graph attachments** (2026-08-16): three independent, stacked bugs found and fixed in the attachment pipeline, the last being a genuine Graph OData incompatibility.
- **Client filters and OTP classifier** (2026-08-21): `client_company_id` filtering added to `GET /tickets`, `/dashboard-stats`, `/sla-overview-counts`, `/audit-logs`, `/interactions` (a shared `ClientFilterSelect.tsx` frontend component, reused across Tickets/Audit Log/Interactions/Dashboard/Reports); Categories converted from a fixed, migration-gated Postgres enum to a dynamically-creatable plain string (new `category:create` permission, new Category Management admin page at `/categories`, new `GET/PUT /categories/{id}/members` endpoints for Team Lead/Staff membership); First Response SLA's OTP-recognition trigger replaced with a pure heuristic text classifier (`otp_classifier.py`) that fixes a real false-positive gap (a support complaint mentioning "OTP" could previously complete the clock); `ticketing-service/frontend`'s last remnant (a stale pre-built bundle) was deleted, leaving that directory empty.

## Known issues carried into this release (see [16-known-limitations](../16-known-limitations/README.md) for full detail)

- Business-critical notification email is unit-tested, not yet live-verified against real SMTP.
- Three backend test files hang if run together (pytest-asyncio event-loop scope issue).
- Deployment topology is ambiguous between a 2-service Render Blueprint and an actively-firing EC2/GitHub-Actions path; `DEPLOYMENT.md` describes neither accurately.
- `ticketing-service/frontend` has no source tree left — only a stale build artifact.

## Breaking changes / migration requirements for anyone on an older checkout

Running `alembic -c alembic_rbac/alembic.ini upgrade head` and `alembic -c alembic_ticketing/alembic.ini upgrade head` against any existing database is required — several migrations in this history are additive-only and safe, but the CRITICAL-priority and ticket-renumbering migrations included one-time data backfills that only ran once against the specific dataset present at that time (see [06-database/migrations.md](../06-database/migrations.md)) — do not expect them to be re-runnable idempotently against a different dataset without checking each migration's own logic first.
